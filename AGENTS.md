# Правила проекта

- Общаться с пользователем на русском языке.
- Frontend расположен в `frontend/`. Использовать pnpm и существующий lockfile.
- Стек: Next.js App Router, React, TypeScript, Tailwind CSS. Не добавлять библиотеки без необходимости и согласования.
- Разрабатываем сайт поэтапно. Текущий этап — только шапка, favicon и hero. Не добавлять каталог, подвал, следующие секции или содержимое страниц услуг без отдельного запроса. Маршруты услуг остаются заготовками с заголовками.
- Сайт посвящён только инженерным сетям и технологическим системам. В раскрывающемся пункте «Услуги» показывать профильные работы из `navigationServices`. Строительство зданий и капитальный ремонт отдельными направлениями не предлагать.
- Ограничения заказчика: компания не разрабатывает проекты. Предлагать монтаж по готовой проектной документации заказчика; не добавлять услуги или обещания проектирования при переносе контента с исходного сайта. Портфолио выполненных объектов подписывать «Наши работы».
- Прочистку, промывку, устранение засоров и телеинспекцию канализации описывать только в комплексном сервисном обслуживании. Не возвращать отдельную услугу, страницу или FAQ об обслуживании канализации. Монтаж и реконструкция канализационных сетей остаются инженерными работами.
- Шапка приближена к sk-tps.ru: без верхней полосы, с пунктом «Услуги», контактами и мессенджерами. Hero использует композицию sigurd-promo.ru/new/, главное фото и сведения — с sk-tps.ru. Не переносить чужие цифры, обещания и лицензии из референса.
- Логотип — `frontend/public/brand/logo.svg`, фирменную геометрию и цвета сохранять. Favicon — файлы в `frontend/app/`. Иконки — `shared/ui/icons.tsx`, без отдельной библиотеки.
- FSD: `_app → _pages → widgets → features → entities → shared`. Папка `frontend/app/` служит адаптером маршрутизации Next.js.
- Импортировать слайсы через публичный `index.ts`. Внутри слайса использовать относительные импорты. Не импортировать соседние слайсы того же слоя.
- Компоненты серверные по умолчанию; `"use client"` добавлять только на интерактивной границе. Серверные секреты и интеграции не экспортировать в клиентский граф.
- Стили: Tailwind и токены в `frontend/src/_app/styles/globals.css`. Сохранять адаптивность, видимый focus и клавиатурное управление.
- Не добавлять мелкие визуальные подсказки и счётчики, которые дублируют очевидное состояние интерфейса, например «Этап 1 из 4» рядом с выбранным этапом.
- Контейнер резиновый, на всю ширину окна с адаптивными боковыми отступами. Не ограничивать шапку и hero фиксированным `max-width`.
- Светлая и тёмная темы обязательны для каждого нового блока. Тема выбирается в шапке, сохраняется в localStorage; первый визит учитывает системные настройки. Использовать семантические токены вместо фиксированных цветов текста и фона.
- Контакты, этапы работ и список услуг находятся в `entities/`. Не дублировать их по компонентам. `/seti` — общий раздел инженерных и технологических систем; отдельные страницы услуг генерируются из `entities/service`.
- БД нет. Серверная логика — только сервис заявок `backend/feedback/` (стандартная библиотека Python, без зависимостей) за Nginx `/api/feedback`. Правила заявки — в `request.py`, доставка (Resend или SMTP) — в `delivery.py`, HTTP-обработчик в `server.py` остаётся тонким. Новую серверную логику выделять модулями по предметной области. Ключ Resend и SMTP-пароль хранятся только в игнорируемом `.env.local` и на сервере в `/etc/sk-tps/feedback.env`; не выводить их и не включать в Git, сборку или клиентский код.
- После изменений запускать подходящие проверки из `frontend/`: `pnpm lint`, `pnpm typecheck`, при структурных изменениях также `pnpm build`.
- Не коммитить, не пушить и не публиковать без прямого запроса пользователя. Не включать в Git `.env`, ключи и артефакты сборки.
- В конце работы с изменениями всегда приводить готовые команды `git add`, `git commit` и `git push` для самостоятельного выполнения пользователем. Сообщения коммитов писать на английском языке. Push выполняет пользователь; не запускать его без отдельного прямого поручения.
- Демо выкладывается статически через `.github/workflows/deploy.yml` на VPS; сборка — `pnpm build:static`. Не добавлять серверные возможности без пересмотра такого деплоя. Сервис заявок устанавливается отдельно скриптом `deploy/install-feedback.sh` от root. Скрипты и Nginx-конфигурация находятся в `deploy/`.
- CI использует отдельный ограниченный SSH-ключ из `SK_TPS_DEPLOY_KEY`, без root и sudo. Host key закреплён в `deploy/known_hosts`; не отключать его проверку. Приватный ключ из `.local/` не читать в вывод инструментов и не включать в коммиты.
