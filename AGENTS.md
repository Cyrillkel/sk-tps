# Правила проекта

- Общаться с пользователем на русском языке.
- Frontend расположен в `frontend/`. Использовать pnpm и существующий lockfile.
- Стек: Next.js App Router, React, TypeScript, Tailwind CSS. Не добавлять библиотеки без необходимости и согласования.
- Разрабатываем сайт поэтапно. Текущий этап — только шапка, favicon и hero. Не добавлять каталог, подвал, следующие секции или содержимое страниц услуг без отдельного запроса. Маршруты услуг остаются заготовками с заголовками.
- Тематика сайта — только инженерные и технологические сети. Строительство зданий и общий капитальный ремонт исключены.
- Шапка приближена к sk-tps.ru: без верхней полосы, с выпадающим меню «Услуги», контактами и мессенджерами. Hero использует композицию sigurd-promo.ru/new/, главное фото и сведения — с sk-tps.ru. Не переносить чужие цифры, обещания и лицензии из референса.
- Логотип — `frontend/public/brand/logo.svg`, фирменную геометрию и цвета сохранять. Favicon — файлы в `frontend/app/`. Иконки — `shared/ui/icons.tsx`, без отдельной библиотеки.
- FSD: `_app → _pages → widgets → features → entities → shared`. Папка `frontend/app/` служит адаптером маршрутизации Next.js.
- Импортировать слайсы через публичный `index.ts`. Внутри слайса использовать относительные импорты. Не импортировать соседние слайсы того же слоя.
- Компоненты серверные по умолчанию; `"use client"` добавлять только на интерактивной границе. Серверные секреты и интеграции не экспортировать в клиентский граф.
- Стили: Tailwind и токены в `frontend/src/_app/styles/globals.css`. Сохранять адаптивность, видимый focus и клавиатурное управление.
- Контейнер резиновый, на всю ширину окна с адаптивными боковыми отступами. Не ограничивать шапку и hero фиксированным `max-width`.
- Светлая и тёмная темы обязательны для каждого нового блока. Тема выбирается в шапке, сохраняется в localStorage; первый визит учитывает системные настройки. Использовать семантические токены вместо фиксированных цветов текста и фона.
- Контакты, этапы работ и список услуг находятся в `entities/`. Не дублировать их по компонентам. `/seti` — общий раздел, отдельные страницы услуг генерируются из `entities/service`; `/stroitelstvo` и `/remont` не создаются.
- Отдельного backend и БД пока нет. При появлении серверной логики выделять модули по предметной области; маршруты не должны содержать бизнес-логику.
- После изменений запускать подходящие проверки из `frontend/`: `pnpm lint`, `pnpm typecheck`, при структурных изменениях также `pnpm build`.
- Не коммитить, не пушить и не публиковать без прямого запроса пользователя. Не включать в Git `.env`, ключи и артефакты сборки.
- Демо выкладывается статически через `.github/workflows/deploy.yml` на VPS; сборка — `pnpm build:static`. Не добавлять серверные возможности без пересмотра такого деплоя. Скрипты и Nginx-конфигурация находятся в `deploy/`.
- CI использует отдельный ограниченный SSH-ключ из `SK_TPS_DEPLOY_KEY`, без root и sudo. Host key закреплён в `deploy/known_hosts`; не отключать его проверку. Приватный ключ из `.local/` не читать в вывод инструментов и не включать в коммиты.
