# Контент, фотографии и городские страницы

## Что перенесено

Источник — https://sk-tps.ru/. Объём услуг взят из раздела `/seti`, проекты найдены через каталоги и sitemap, фотографии собраны также из внутренних галерей. Перенесены 23 проекта и 205 уникальных исходных фотографий: 191 фотография галерей и ещё 14 отдельных обложек каталогов. Ошибок скачивания нет.

Полный проверенный реестр — [project-photo-manifest.json](project-photo-manifest.json). Он связывает исходную страницу, URL оригинала, локальные файлы, размеры и SHA-256. Данные сайта находятся в `frontend/src/entities/project/model/projects.json`; в галереи передаются только необходимые поля изображения.

Исходные страницы проектов содержат заголовки и фотографии, без описаний сроков, стоимости или условий работ. Эти сведения не придуманы. Заголовки двух лестниц уточнены по фотографиям, опечатка в названии проекта АБК исправлена. Исходные заголовки сохранены в `sourceTitle`. Местоположение объекта привязано к городу только там, где оно явно указано источником; соседство и названия заказчиков не считаются доказательством адреса.

Направления строительства и общего ремонта сохранены как выполненные проекты, без добавления таких услуг в навигацию. Обслуживание канализации представлено в составе комплексного обслуживания; монтаж и реконструкция сетей — самостоятельный вид инженерных работ.

## WebP и проверка полноты

Для каждой фотографии созданы два файла в `frontend/public/images/projects/`:

- полная версия WebP до 2200 px по длинной стороне, качество 80;
- превью WebP до 640 px по длинной стороне, качество 72.

Изображения меньшего размера не увеличиваются. Всего 410 файлов. Исходники занимали 75 964 014 байт; WebP вместе с превью — 49 402 450 байт, примерно на 35% меньше. Это сравнение веса файлов, а не измерение скорости сайта. Сетка галереи загружает превью по мере прокрутки; полное фото запрашивается при открытии. Обложка первого экрана использует полную версию с приоритетной загрузкой.

Оригиналы и служебные HTML сохранены локально в игнорируемой `.local/migration/`, в Git их нет. Секретов в реестре нет. Для повторного импорта нужен полный `.local/migration/projects-manifest.json` либо путь к его копии:

```bash
python3 scripts/import-projects.py
python3 scripts/verify-content.py
```

Проверка работает и без `.local/`: сверяет опубликованный реестр с данными сайта, исходными URL, подписями формата WebP и контрольными суммами всех файлов. После сборки дополнительно проверяются полнота галерей в HTML, 39 страниц, заголовки, descriptions, собственные canonical и sitemap:

```bash
cd frontend
pnpm lint
pnpm typecheck
pnpm build:static
cd ..
python3 scripts/verify-content.py --build
```

## Как добавлять города

Сейчас на главной показаны три области и списки 22 городов. Городских маршрутов, ссылок и записей sitemap ещё нет. Шаблон `_pages/city` и тип `CityLandingContent` в `entities/geography` подготовлены для следующего этапа.

Общий шаблон можно использовать повторно. Для публикации нужны фактические сведения о работе в конкретном городе: условия выезда, особенности объектов и обслуживания, подтверждённые местные проекты при наличии. Нельзя выдавать один объект за проекты в нескольких городах или придумывать местный офис. Уникальный текст сам по себе не гарантирует отсутствие дублей или позиции в поиске. Подмена одного названия города создаёт малоценные страницы; массовые похожие страницы могут подпадать под [правила Google о дорвеях](https://developers.google.com/search/docs/essentials/spam-policies#doorway-abuse).

Последовательность публикации:

1. Добавить в `cityLandings` сведения для конкретного города: description, introduction, workConditions, подтверждённые projectSlugs. Сначала статус `draft`.
2. Проверить факты и полезность страницы, затем выставить `published`. Шаблон отклоняет публикацию без обязательного содержания; редакционная проверка всё равно нужна.
3. При первой публикации добавить тонкий адаптер `app/goroda/[city]/page.tsx` и генерацию параметров только для `published`. В текущем статическом режиме Next.js не собирает динамический маршрут с пустым набором параметров, поэтому адаптера пока нет.
4. В адаптере подключить `CityPage` и `generateCityMetadata` через публичный API `_pages/city`. Неизвестные и неопубликованные города должны возвращать 404.
5. В географии превратить название только опубликованного города в ссылку, добавить его в sitemap и связать с подходящими услугами и реальными проектами.

Для города предусмотрен собственный canonical вида `https://sk-tps.ru/goroda/kaluga/`. Canonical указывает предпочтительный URL страницы; он не делает одинаковый контент уникальным. См. [документацию Google о дублях и canonical](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls). Не следует направлять все городские canonical на главную, если эти страницы предназначены для самостоятельного поиска.

## Перед заменой действующего сайта

22 адреса проектов без расширения сохранены, с завершающим `/` в статической сборке. Дополнительный проект «Реконструкция дезбарьера ООО „ЭлинарСтройИнвест“» найден по адресу `/page139288356.html`; в новом сайте он доступен по `/rekonstrukciya-dezbarera/`. На production потребуется 301 со старого адреса на новый. В этом изменении серверные редиректы не настраивались.

`metadataBase`, canonical, Open Graph и sitemap указывают будущий основной домен `https://sk-tps.ru`. При смене домена нужно обновить `shared/config/site.ts`. Демо продолжает отдавать существующий заголовок Nginx `X-Robots-Tag: noindex, nofollow, noarchive`; перенос шаблонов не открывает демо для индексации. Перед запуском основного домена отдельно проверяются редиректы, индексирование, sitemap и актуальность контактов.
