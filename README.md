# СК «Техпромстрой»

Поэтапная разработка сайта об инженерных и технологических системах на Next.js App Router, React, TypeScript и Tailwind CSS. Контент и фотографии: https://sk-tps.ru/. Композиция hero: https://sigurd-promo.ru/new/.

## Запуск

Нужны Node.js 20.19+ и pnpm 10.10.0.

```bash
cd frontend
pnpm install
pnpm dev
```

Сайт доступен на http://localhost:3000.

```bash
pnpm lint
pnpm typecheck
pnpm build:static
```

`build:static` использует Webpack и создаёт статический сайт в `frontend/out/`, как в CI. Для стандартного сервера Next.js доступен `pnpm build`. Если окружение запрещает служебный локальный порт Turbopack, для разработки используйте `pnpm dev --webpack`.

## Структура

```text
frontend/
├── app/                 # Маршруты и специальные файлы Next.js
└── src/
    ├── _app/            # Корневой layout, metadata и глобальные стили
    ├── _pages/          # Композиция страниц
    ├── widgets/         # Разделы главной, содержимое услуг и проектов, шапка и подвал
    ├── features/        # Навигация, галереи, слайдеры, тема и связь
    ├── entities/        # Компания, услуги, проекты и география работ
    └── shared/          # Общие компоненты без бизнес-логики
```

Слои FSD `_app` и `_pages` названы с префиксом, чтобы избежать конфликта с зарезервированными папками Next.js. Файлы `app/` подключают страницы через публичные API слайсов. Импорты направлены в нижние слои; между слайсами одного слоя импортов нет. Внутри слайса используются относительные импорты, снаружи — его `index.ts`. ESLint проверяет направления импортов и запрет обращения к внутренним файлам слайсов через alias.

Компоненты по умолчанию серверные. Клиентские границы нужны для интерактивных элементов: навигации, галерей, слайдеров и темы. Цвета и шрифты заданы токенами в `src/_app/styles/globals.css`. Общий контейнер занимает всю ширину окна с боковыми отступами 20, 32 или 40 px по брейкпоинтам, без фиксированного `max-width`.

## Текущий объём

Главная содержит направления услуг, выполненные инженерные проекты, сведения о компании, документы, благодарственные письма, порядок работы, географию и контакты. Блок «География работ» показывает 22 города Калужской, Тульской и Московской областей. Сейчас названия городов — обычный текст; городские страницы и ссылки на них ещё не публикуются.

Логотип находится в `public/brand/logo.svg`: это векторная копия [полного PNG с исходного сайта](https://static.tildacdn.com/tild3932-3138-4064-a136-663239653362/photo.png), с прозрачным фоном и надписью в контурах. Favicon представлен SVG, ICO и Apple touch icon в `app/`. Общие SVG-иконки находятся в `shared/ui/icons.tsx`.

`/seti/` — каталог инженерных и технологических систем. Один шаблон обслуживает 11 страниц услуг с отдельным содержимым, составом работ, вопросами и связанными проектами. Данные находятся в `entities/service`. Прочистка и обслуживание канализации входят в комплексное сервисное обслуживание; отдельная страница прочистки не генерируется. Монтаж и реконструкция канализационных сетей остаются видом инженерных работ.

Компания не разрабатывает проекты: монтаж предлагается по готовой проектной документации заказчика. Портфолио подписано «Наши работы». При переносе контента нельзя добавлять предложения проектирования или упоминания обслуживания канализации вне комплексного сервисного обслуживания; ограничения закреплены в `AGENTS.md`.

`/proekty/` — портфолио из 23 проектов с исходного sk-tps.ru. В него перенесены все 205 уникальных фотографий из карточек и внутренних галерей. Исторические проекты монтажа конструкций и ремонта сохранены в портфолио; строительство зданий и капитальный ремонт отдельными услугами не предлагаются. Основные 22 адреса проектов сохранены, для найденной в sitemap страницы `/page139288356.html` выбран понятный адрес `/rekonstrukciya-dezbarera/`. Перед заменой действующего сайта для старого адреса потребуется 301-редирект.

Фотографии проектов хранятся локально в WebP: полные версии до 2200 px и превью до 640 px. Карточки и сетки используют превью с ленивой загрузкой, открытая галерея — полную версию. Галереи поддерживают стрелки, клавиатуру, свайпы и циклическое переключение; при увеличении снимка свайп не меняет фото. Мобильный слайдер услуг также зациклен. В правом нижнем углу расположена раскрывающаяся кнопка мессенджеров.

Карточки выполненных работ используют общий `shared/ui/CardCarousel` на Swiper: 1,3 карточки до 768 px, 2,3 от 768 px и 3,3 от 1024 px. Компонент подключён на главной, в каталоге работ, на страницах услуг и объектов, а также в шаблоне города. Есть зацикливание, стрелки, свайп, перетаскивание мышью и клавиатурное управление внутри карусели. Движение учитывает настройку уменьшенной анимации. Для 2–4 карточек повторяется полный набор слайдов, чтобы Swiper мог поддерживать непрерывный цикл; единственная карточка показывается без навигации. Все карточки и ссылки присутствуют в серверном HTML.

Автопрокрутка карточек работ использует модуль Swiper Autoplay: пауза между переходами 3 секунды, плавный переход 1800 мс с постепенным разгоном и замедлением, цикл продолжается после последней карточки и ручного переключения. При наведении мыши прокрутка приостанавливается, после ухода указателя продолжается. В управлении оставлены стрелки; отдельной кнопки паузы нет. При системной настройке уменьшенного движения или единственной карточке автопрокрутка отключена.

Шаблон будущей городской страницы находится в `_pages/city`, справочник регионов и городов — в `entities/geography`. Для каждой опубликованной страницы заданы title, description и собственный canonical; `sitemap.xml` содержит только существующие страницы. Подробности переноса, проверки фотографий и подготовки городских страниц описаны в [docs/content-and-geography.md](docs/content-and-geography.md).

`/contacts` сохраняет простой блок контактов с исходного сайта. Кнопки связи в шапке и hero ведут на эту страницу.

Светлая и тёмная темы доступны в шапке. Выбор хранится в `localStorage` под ключом `sk-tps-theme`, при первом визите учитывается системная тема. Скрипт в корневом layout применяет тему до отрисовки, переключатель подписывается на её изменения через `useSyncExternalStore`. Цвета шапки, меню и hero заданы семантическими CSS-токенами; вариант логотипа для тёмного фона сохраняет фирменный знак и использует светлую надпись.

Отдельного backend, базы данных и серверной отправки заявок пока нет. Связь ведёт в телефон, почту и мессенджеры. Route Handler или Server Action потребует пересмотра текущего статического размещения. Если появится бизнес-логика, она размещается в отдельных серверных модулях, а обработчик остаётся тонким.

## Демо и автодеплой

Адрес после настройки VPS: http://177.203.49.191/. Workflow `.github/workflows/deploy.yml` запускается после push в `main` или вручную через Actions. Он устанавливает зависимости по lockfile, проверяет код, выполняет `pnpm build:static`, передаёт каталог `out/` по SSH и проверяет идентификатор опубликованной версии по HTTP.

Для демо используется статическая выгрузка Next.js (`NEXT_OUTPUT=export`). Серверные функции при такой сборке недоступны. Обычная сборка `pnpm build` сохраняет стандартный режим Next.js. При добавлении серверной логики способ размещения нужно изменить.

На VPS нужен Nginx и пользователь `deploy-sk-tps` без `sudo`. Однократную настройку выполняет `deploy/bootstrap.sh`, которому передаётся только публичный ключ CI. Перед запуском скрипта требуется согласование установки пакетов и изменения конфигурации сервера. Ключ CI разрешает только команду публикации; права root и обычный shell ему не предоставляются. Публичный host key сервера закреплён в `deploy/known_hosts` и получен через существующее проверенное SSH-соединение.

Приватный ключ добавляется напрямую в GitHub: **Settings → Secrets and variables → Actions → New repository secret**, имя `SK_TPS_DEPLOY_KEY`. Значение ключа не отправляется в чат и не попадает в Git. Локальный файл ключа хранится в игнорируемом `.local/deploy/ci_ed25519` с правами `0600`. При доступном GitHub CLI секрет можно добавить без вывода ключа: `gh secret set SK_TPS_DEPLOY_KEY --repo Cyrillkel/sk-tps < .local/deploy/ci_ed25519`.

Каждая сборка загружается в отдельный каталог `/srv/sk-tps/releases/`. После проверки обязательных файлов атомарно переключается ссылка `current`; ошибочная загрузка не затрагивает текущую версию. Хешированные JS/CSS предыдущих версий сохраняются в `shared/`, чтобы открытые вкладки могли загрузить старые ресурсы. Автоматического удаления релизов пока нет. Демонстрационный Nginx добавляет `X-Robots-Tag: noindex, nofollow, noarchive` и раздаёт сайт по HTTP на порту 80.
